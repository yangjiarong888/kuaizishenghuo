# 四舍五入与个人中心安全迁移设计

日期：2026-08-17

## 背景

`agent/rounding-my-profile-scripts` 基于旧 `main` 开发，包含四舍五入支付、个人中心和 workflow 能力。当前 `agent/charge-page` 已完成商城拆分、外卖安全边界、海运与设备测试隔离。直接合并会在三个核心文件产生架构冲突，并重新引入默认支付密码与自动密码输入，因此采用能力提取而非旧代码覆盖。

## 目标

- 将货到付款取整计算及可验证 UI 操作迁入当前模块化商城和外卖流程。
- 将个人中心的只读导航与页面识别迁入独立入口。
- 引入统一 workflow 结果模型和登录状态检测。
- 保持默认不提交订单、不修改账户、不自动输入支付密码。
- 完成后合并、推送并清理旧分支和旧工作树。

## 不在本次范围

- 修改手机号、昵称、邮箱、登录密码或支付密码。
- 开关指纹支付、注销账户、隐私授权重置或清除缓存。
- 自动输入余额支付密码，包括旧版默认值 `123456`。
- 真实设备、模拟器真实订单或账户状态测试。
- 恢复旧版商城单体实现或覆盖当前 Mixins。

## 组件设计

### 取整支付模块

迁入独立 `RoundingPaymentMixin` 及纯函数类型。纯计算负责从应付金额生成递增的整数候选和找零金额；UI 层只在可验证的货到付款结算上下文中定位、选择并回读取整金额。元素缺失、重复、不可用、金额不一致或回读失败均失败关闭。

商城的 `MallOrderFlow` 在当前 Address、Cart、Checkout Mixins 之外组合取整能力。外卖的 `TakeoutCheckoutMixin` 组合相同能力，但保留当前人工余额支付等待，不迁入任何密码输入方法。

CLI 增加 `--rounding-payment` 和可选 `--rounding-amount`。取整只允许与 `payment_method=cod` 组合；自定义金额必须同时启用取整并严格大于原应付金额。订单提交继续受现有 `--submit-order` 控制，默认只预览。

### 个人中心

迁入精简后的 `MyProfilePage`，仅包含“我的”Tab 识别、只读入口遍历、目标页标记校验和返回。独立入口 `scripts/run_my_profile_navigation.py` 默认导航巡检并在结束时关闭自有 Driver。

页面不得包含写入个人资料、验证码、密码、指纹支付、注销、隐私重置或设置开关的方法与参数。遇到敏感页面只验证入口或立即返回，不点击最终确认。

### Workflow

迁入 `WorkflowResult`、状态和阶段枚举，以及无副作用的登录状态检测。外卖 workflow 改为显式接收 `submit_order`，默认 `False`；只有调用方显式授权时才将该值传给当前 checkout 流程。若已提交但取消或结果确认失败，返回独立的清理失败状态，不把它报告成普通失败或成功。

## 数据流与安全门

CLI 参数先完成组合校验，再创建 Driver。结算流程依次完成商品/地址/配送/支付方式校验，随后可选选择并回读取整金额。未传 `--submit-order` 时在最终提交前返回。提交后沿用当前精确订单身份、结果确认和取消边界。

个人中心入口只创建页面对象并执行只读导航；任何可修改账户状态的操作均不进入本次代码路径。

## 迁移方式

从旧分支按文件和能力提取，不合并旧分支的三个冲突文件。新增模块先迁入并以旧测试为素材重写适配测试，再在当前实现中增加最小接线。每个能力都遵循 RED、GREEN、回归验证。

## 验证

- 纯函数覆盖零值、整千金额、小额、大额、自定义金额和找零精度。
- 商城 CLI 覆盖默认不提交、非法参数组合、COD 取整参数传递及金额回读。
- 外卖覆盖 COD 取整、余额支付不进入取整、提交标记与取消失败状态。
- 个人中心覆盖允许入口清单、敏感方法/CLI 参数不存在、导航失败关闭。
- Workflow 覆盖默认 `submit_order=False`、显式提交传递和已提交清理失败。
- 运行完整默认离线测试；设备测试保持排除。

完成标准是离线测试全绿、无冲突标记、无默认密码、无自动密码输入、当前商城/外卖/海运安全回归通过。真实设备测试继续暂停。
