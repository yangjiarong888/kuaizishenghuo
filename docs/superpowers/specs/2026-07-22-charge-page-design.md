# 充值缴费 ChargePage 设计说明

## 目标

新增 `pages/charge_page.py` 和 `testcases/test_charge_page.py`，把九张充值缴费需求图中的页面识别、输入、选择、跳转与安全校验封装成可复用的 Appium Page Object，并通过不依赖真实设备的 pytest 单元测试验证业务行为。

## 范围

`ChargePage` 覆盖以下页面与操作：

- 充值缴费首页与独立话费流量页：进入页面、`+63` 默认区号、手机号输入、话费/流量切换、套餐选择、优惠券选择、底部功能入口。
- 生活缴费首页：电费、水费、网费、拍照缴费入口及账号管理、缴费客服、缴费必看、缴费记录入口。
- 电费、水费、网费：供应商选择、动态字段填写、缴费金额、账单图片、保存或更新账号、创建订单前校验。
- 拍照缴费：账单图片必填、最多两张、缴费金额填写。
- 账号管理：列表识别、复制、编辑、删除及编辑保存。
- 缴费记录：类型切换、进入详情、管理模式、选择、全选和删除。

本次不新增命令行运行器，不修改现有页面对象，也不连接真实支付或实际创建订单。

## 结构

仅新增一个 `ChargePage` 类。类内按业务域排列常量与公开方法，公用的查找、点击、输入、文本读取、等待和滚动能力由私有方法统一承载。供应商及其输入字段使用声明式配置表示，避免为每个供应商复制相同流程。

定位策略优先使用资源 ID；由于需求图不包含页面 XML，首版同时提供中文文案、`content-desc` 和控件类型兜底。资源 ID 常量集中定义，后续获取真实 XML 后可替换常量而不改变调用接口。

## 公开接口

- `wait_for_charge_home()`：确认充值缴费首页关键元素存在。
- `enter_from_home()`：从首页点击“充值缴费”并等待目标页。
- `enter_life_payment(kind)`：进入电费、水费、网费或拍照缴费。
- `set_phone_number(number)`：输入手机号；保留页面默认 `+63`，清理号码中的空格。
- `switch_recharge_type(kind)`：切换话费或流量。
- `select_recharge_package(label)`：按套餐文案选择套餐。
- `select_coupon(label=None)`：打开优惠券并选择指定或第一张可用券。
- `open_bottom_entry(label)`：打开套餐查询、缴费客服、充值必看或充值记录。
- `select_provider(name)`：选择生活缴费供应商。
- `fill_billing_fields(values)`：按字段标签填写账号、用户名、手机号或缴费金额。
- `add_bill_photos(paths, limit)`：按业务限制上传账单图片；电费和水费选填且最多一张，网费不上传图片，拍照缴费必填且最多两张。
- `set_save_account(enabled)`：设置“保存或更新已有的账号”。
- `is_provider_account_unique(provider, current_provider=None)`：保存前检查同一供应商是否已有账号。
- `create_order(submit=False)`：验证必填信息；仅在 `submit=True` 时点击创建订单。
- `switch_payment_record_type(kind)`：切换手机费、电费、网费、水费或拍照记录。
- `manage_payment_records(action, record_label=None)`：进入管理模式并执行选择、全选或删除。
- `manage_saved_account(action, account_label)`：复制、编辑或删除已保存账号。
- `verify_saved_account_order()`：确认账号按电费、水费、网费顺序展示。
- `edit_saved_account(account_label, values)`：在目标账号卡片内进入编辑，填写账号/用户名并保存。

参数不合法时抛出 `ValueError`；页面元素缺失、页面未到达或交互失败时返回 `False`。公开动作成功时返回 `True`。

## 业务约束

- 手机号默认区号为 `+63`，首版不自动切换国家区号。
- 话费与流量套餐默认选择页面展示的第一个可用项。
- 仅展示并选择生活缴费优惠券；没有可用券时不把不可用券当作可选项。
- 电费供应商合并 Meralco 相关入口；不保留旧的 `PELCO1`、`PELCO2` 选择。
- 水费支持 Manila Water、Maynilad、Prime Water。
- 网费支持需求图列出的供应商，并允许配置新增供应商字段。
- 图片数量在点击上传控件前校验，超过限制直接抛出 `ValueError`。
- 电费和水费账单图片选填且最多一张；网费不上传图片；拍照缴费图片必填且最多两张。
- 账号、用户名、金额等必填规则由当前缴费类型和供应商配置决定。
- 默认不提交订单，避免测试或误调用污染业务数据。
- 账号管理按电费、水费、网费排序；同一供应商只保存一个账号的约束由页面操作前校验提示风险，不伪造后端状态。
- 缴费记录覆盖手机费、电费、网费、水费、拍照五类；删除操作必须显式调用。

## 测试设计

`testcases/test_charge_page.py` 使用 FakeDriver/FakeElement 模拟 Appium API，严格采用测试先行：

- 首页识别、入口点击和目标页等待。
- 手机号空格清理、默认区号校验、非法号码拒绝。
- 话费/流量切换、套餐选择和优惠券可用性。
- 四类生活缴费入口。
- 供应商选择和动态字段输入。
- 各业务图片上限及拍照缴费图片必填。
- 保存账号开关。
- `submit=False` 不点击创建订单，`submit=True` 才允许点击。
- 账号复制、编辑、删除。
- 账号排序识别与编辑保存。
- 五类缴费记录切换、详情、选择、全选和删除。
- 元素缺失、必填字段缺失和不支持枚举值的失败行为。

单元测试不声称验证真实 resource-id、系统相册、真实页面跳转或支付结果；这些需要连接 Appium 设备并获取页面 XML 后再做集成验证。

## 验收标准

- 两个指定文件存在且可以被 Python 导入。
- 新增 pytest 用例全部通过，现有 pytest 回归不受影响。
- 新增公开方法均有至少一个先失败、后通过的测试。
- 不使用固定 `sleep`；等待统一使用显式等待或可测试的立即查询。
- 默认路径不会点击“立即充值”或“创建订单”。
- 日志和异常不输出手机号、账号、图片路径等敏感数据。
