# 海运真实首页导航修复设计

日期：2026-08-17

## 背景与证据

夜神模拟器中的真实应用停在“我的”Tab。现有海运脚本只有在找到测试约定的 `app_home_root` 或“筷子生活首页”描述后，才允许点击“国际货运”。真实应用未暴露这些标识，因此脚本在创建订单前失败关闭。

只读导航探针确认：真实主界面存在且仅存在一个可见“首页”元素；点击后存在且仅存在一个可见“国际货运”元素，当前包名为 `com.bs.feifubao`。

## 方案比较

1. **真实文本导航契约（采用）**：确认当前应用包，唯一定位并点击底部“首页”，再唯一定位“国际货运”。优点是符合真实页面且能失败关闭；缺点是依赖稳定中文文案。
2. **坐标点击**：实现快，但受分辨率、缩放和布局变化影响，无法可靠验证目标，不采用。
3. **继续依赖合成 root 标识**：单元测试稳定，但真实应用没有对应标识，不能解决问题，不采用。

## 行为设计

`enter_from_app_home` 先确认当前包为配置中的应用包。若已处于可验证的海运首页则直接成功；否则必须找到唯一、可见且可用的“首页”元素并点击。点击后必须等待唯一、可见且可用的“国际货运”入口出现，然后点击并继续使用现有海运首页身份校验。

任何查询异常、元素缺失、重复、不可见、不可用、点击异常或目标页超时均返回失败并记录脱敏诊断。不得使用坐标兜底，不得在不确定时重复点击“国际货运”，也不得改变地址、配送日期、提交一次性保护或余额支付逻辑。

## 测试设计

先添加失败测试，再做最小实现：

- 从“我的”Tab 经唯一“首页”进入并点击唯一“国际货运”。
- 已在应用首页时仍可正常进入。
- 包名错误时失败且不点击。
- “首页”或“国际货运”缺失、重复、不可用或查询异常时失败且不越过对应安全门。
- 点击首页后入口未出现时失败。
- 现有海运导航、地址、配送、支付及 CLI 回归保持通过。

实现完成后只做无下单真实导航验证：到达海运首页后立即关闭 Driver。真实订单需要用户重新在本机配置临时地址和余额密码，并再次明确继续后才执行一次。
