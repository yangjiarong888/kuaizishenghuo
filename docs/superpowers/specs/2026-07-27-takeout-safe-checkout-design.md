# 外卖安全结算设计

## 目标

把外卖脚本的“浏览/结算预览”和“真实下单”明确分开，删除生产代码中的固定支付密码，并保证最终真机回归默认不创建订单、不支付、不发送验证码、不修改地址。

## 已确认的现状

- `scripts/run_takeout_wangwang.py --checkout` 当前会执行加购、结算、支付、订单断言和取消订单。
- CLI 的 `--password` 默认值为 `"123456"`。
- `TakeoutCheckoutMixin.shop_enter_pay_password()` 和 `run_shop_checkout_pay_and_cancel_flow()` 也使用 `"123456"` 作为默认参数。
- 当前入口在 Driver 创建前没有区分“预览结算”和“真实提交”。

## 方案选择

采用“默认预览、显式提交、真实余额支付由用户在真机手动输入”的方案。

不采用以下方案：

- 不继续保留源码固定密码，因为它可能误用于其他环境或账号。
- 不把密码作为普通 CLI 参数，因为它可能进入终端历史和进程参数。
- 本阶段不增加环境变量自动输密码；若以后确需无人值守支付，应单独设计、授权和审查。

## CLI 契约

### 无参数或不带 `--checkout`

只进入目标外卖店铺，保持现有导航行为。

### `--checkout`

执行店内选品、加购和结算页准备，完成优惠券、配送时间、取件码、通知方式和备注等页面配置，但停在最终提交动作之前。

该模式不会：

- 点击最终提交/确认支付；
- 创建订单；
- 进入支付密码输入；
- 执行取消订单。

结算预览可能在当前账号购物车中留下测试商品，因此不作为最终“零业务数据变化”的真机验收路径。最终无副作用回归使用不带 `--checkout` 的导航模式。

### `--checkout --submit-order`

允许执行真实提交。该参数组合具有业务副作用，日志必须明确提示“将创建真实订单”。

- 余额支付：脚本进入支付密码页后停止自动按键，由用户在真机手动输入；脚本只等待订单详情/可取消状态出现。
- 货到付款：无需支付密码，但仍会创建真实订单，因此同样必须显式使用 `--submit-order`。
- 下单成功后保留现有订单断言和取消流程。

### 非法组合

`--submit-order` 未同时提供 `--checkout` 时，在创建 Driver 前返回退出码 `2`。错误日志只描述参数组合，不输出任何个人信息或敏感值。

删除 `--password` 参数。传入旧参数时由 `argparse` 按未知参数拒绝，不做静默兼容。

## 代码边界

### `scripts/run_takeout_wangwang.py`

- 提取 `build_parser()`，便于离线验证默认值。
- 将 `main()` 改为 `main(argv=None)`。
- 增加 `--submit-order`，默认 `False`。
- 增加 `validate_args(args)`，并在 Driver 创建前运行。
- 删除 `--password` 及其调用参数。

### `pages/takeout_checkout_mixin.py`

- 将结算准备和真实提交分为两个明确阶段。
- 预览阶段在最终确认动作前返回成功。
- 提交阶段只有收到 `submit_order=True` 才能点击最终确认。
- 余额支付不再自动输入密码，只等待用户完成真机输入并进入订单详情。
- 删除固定密码默认值；若 `shop_enter_pay_password()` 没有其他调用者，则删除该自动输入方法。
- 保持货到付款、订单详情断言和取消流程的现有业务顺序。

## 数据流

1. CLI 解析参数。
2. `validate_args()` 在任何 Driver/Appium 操作前拒绝危险组合。
3. 创建 Driver 并进入目标店铺。
4. 未指定 `--checkout`：结束。
5. 指定 `--checkout`：执行结算准备并停在最终确认前。
6. 同时指定 `--submit-order`：继续最终确认。
7. 余额支付由用户在真机输入密码；脚本不接收、不记录密码。
8. 检测订单详情后执行断言和取消。

## 异常与超时

- CLI 安全校验失败返回 `2`。
- Driver 创建、页面操作或业务断言失败返回 `1`。
- 手动支付等待使用显式可配置超时；超时只报告未进入订单详情，不推断密码是否正确，也不记录页面中的敏感文本。
- 预览模式若越过最终确认边界，视为安全回归失败。
- 真实提交或取消失败时保留诊断证据，但 page source 必须继续使用公共脱敏接口。

## 测试策略

### 离线 CLI 测试

- 默认 `checkout=False`、`submit_order=False`。
- 解析器不再提供固定密码或 `--password`。
- `--submit-order` 单独使用时在 Driver 创建前返回 `2`。
- `--checkout` 不把 `submit_order=True` 传给业务流。
- `--checkout --submit-order` 显式传递真实提交意图。

### 页面流单元测试

- 预览模式不会调用最终确认、支付密码或取消订单。
- 提交模式保持先准备结算、再最终确认、再订单断言、最后取消的顺序。
- 余额支付调用手动等待，不调用自动密码按键。
- 货到付款跳过手动支付等待。
- 手动等待超时返回失败，不泄漏敏感值。

### 回归与真机

- 每个实现批次运行聚焦测试和完整 `not device` 离线测试。
- 编译全部 Python 文件并扫描固定支付密码。
- 最终真机无副作用验证只执行外卖导航/进店，不带 `--checkout` 或 `--submit-order`。
- 真实下单验证不属于默认验收；只有用户当次明确授权后才执行，并由用户在真机手动输入支付密码。

## 验收标准

- 生产源码不存在固定支付密码 `"123456"`。
- 默认路径和 `--checkout` 路径都不会创建订单。
- 只有 `--checkout --submit-order` 能触发最终确认。
- 自动化代码、命令行、日志和报告均不接收或输出支付密码。
- 所有离线测试零失败，最终真机无副作用路径通过后才结束本业务域验证。
